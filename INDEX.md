> **For AI agents**: Read [CLAUDE.md](CLAUDE.md) first (the protocol). Then [board.md](board.md) and [conventions.md](conventions.md) before any board action. Use the matching [template](templates/) before drafting an item. Pull live board state with JQL — don't treat a log entry as current truth.

## Current Focus

This diary is the canonical guide for MMM project management on the **AW — Automation workstreams** Kanban board. It encodes how the `DataScience` team writes Initiatives, Epics, and Stories, ensures every item is trackable, and runs its cadence. The board is organized under **five Initiatives** — **v0.17** (`AW-152`, historical), **v0.19** (`AW-153`, active PyMC-Marketing model work), **Modeling Infrastructure** (`AW-243`, cross-cutting non-versioned capabilities), and the reporting-layer pair **InsightCore API v2** (`AW-248`) and **InsightCore GUI v2** (`AW-249`); see the routing rule in [board.md](board.md#initiative-structure). Agents **draft by default and write to Jira only on explicit request, confirming first**, and **never reference the diaries in any Atlassian product — Jira or Confluence** (hard rule — see [conventions.md](conventions.md)).

## How We Work (the essentials)

- **Hierarchy:** Initiative → Epic → Story. Every Epic links to an Initiative; every Story to an Epic.
- **Spike & Bug:** Story variants (AW has no such types) — `[Spike]` / `[Bug]` prefix + purpose-built body.
- **Labels:** `DataScience` always, `Modeling` almost always, plus specifics.
- **Title prefixes:** `[Data]` `[Spike]` `[Build]` `[Deploy]` `[Delivery]` `[Bug]` `[QA]`.
- **Statuses:** Backlog → In Progress → Done. New work lands in Backlog.
- **No diary refs (hard rule):** no Atlassian content — Jira items or Confluence pages/comments — ever references the agentic diaries — see [conventions.md](conventions.md).

- [2026-08-11: Seeded-Optimizer Close-Out and the Retirement of the API Phase](log/2026-08-11-seeded-optimizer-closeout-and-api-phase-retirement-jperigo.md) — The GUI phase shipped the day after it was planned, planners signed off, and the owner closed the whole line: **AW-327 closed on what shipped** (AW-329 / AW-330 / AW-333 delivered; AW-331 half, AW-332, AW-334 retired) and **AW-328 retired undelivered** with all four stories, no API work ever started. Two practices recorded. **When delivery diverges from the written story, amend the ACs to describe what exists, add a scope note naming what was dropped, then close** — closing as-written would have left the board asserting a Scenario Results entry point and asymmetric bands exist, neither of which was built. Follow-up: the `deploy_api.sh` `$APP_DIR` guard is now tracked by **no** board item, having ridden on the retired AW-338, after two production incidents.
